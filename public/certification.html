Certification Roadmap

Tenna ELD · Updated 15 September 2026

1. Basis

  • ELD registration is self-certification under 49 CFR 395, Subpart B, Appendix section 5. There is no third-party lab, no fee, and no FMCSA-administered test. The certifying statement must describe how the model was tested for compliance with the technical specifications.
  • The reference test method is FMCSA's ELD Test Plan and Procedures, version 2.1 (18 July 2017). It is not binding on providers, but it is the procedure FMCSA uses if it independently evaluates a listed device.
  • The test plan breaks Appendix section 4 down into a Requirements Traceability Matrix (RTM) of 347 numbered requirements (ELD-FUNC-4.x) in eight categories: Accounts, Vehicle Interface, ELD Inputs, Processing, Recording, Monitoring, ELD Outputs, Data Transfer. Test procedures are grouped in three chapters: (1) Accounts, Inputs and Vehicle Interface; (2) Processing, Monitoring and Recording; (3) Outputs and Data Transfer.
  • All test evidence in this roadmap traces to RTM requirement IDs. The RTM and chapter structure are followed; the written step sequences are not, because several do not produce correct results on real vehicles. One exercise may cover several requirements.
  • Test plan requirements for the record itself: every step scored pass or fail; report lists date, tester, result, comments, and the re-run set for each failure; regression test after every corrective action; test records retained two years; tests run with multiple driver accounts from different states already created and the driver logged in.

Stage D — Transfer and host reporting

Owner: AppAxis · Phase 4, weeks 13–15

  • Telematics transfer to eRODS (4.9, 4.10.1.1 web services, 4.10.1.2 email) from the driver at roadside (D17) and from the back office (W17, one month per request). No-signal path: inspection display on the phone (D16).
  • Per FMCSA's ELD Data Transfer Requirements sheet (Tom Cuthbertson, 10 September): web services is a SOAP submission of the client certificate, the output file and the output file comment, with a test flag that keeps submissions away from inspectors; email is S/MIME, AES-256 encrypted with FMCSA's public key and signed with the provider's private key, subject "ELD records from <registration id>:<ELD identifier>", "TEST:" prefix while testing. FMCSA issues a test certificate, sample ELD identifier and sample registration id before registration, so transfer development does not wait on Stage F. Key handling lives on the ELD backend, not the phone.
  • Generate the output file continuously through testing and run every file through FMCSA's file validator, then web eRODS. Both tools need the provider account (Stage E), so open it once the app is running in trucks internally, not before.
  • Unidentified-driving loop end to end: tracker capture, 8-day in-cab list, driver accept or reject (D22), carrier reason or reassignment (W16), driver confirmation (D34), 6-month retention kept as whole calendar months, legal hold suspending the purge (W15).
  • Daily transfer self-test per device (4.6.1.7, Tom's cadence): a TEST-flagged submission of the real log with "24-hour test" in the comment field; three consecutive failures raise the data-transfer malfunction (W10).
  • Edit and annotation versioning with originals preserved and full attribution. Wrong-driver segment reassignment with both drivers' acceptance.
  • Host inspector view (W18).

Exit. Roadside and host-initiated transfers accepted by the eRODS test endpoint on a test fleet. Evidence: transfer confirmations and test-fleet session record.

Stage F — Registration, listing, and maintenance

Owner: Tenna, AppAxis supporting · Phase 5, weeks 17–19, then ongoing

  • Registration (Appendix 5.1): provider name, address, contact, ELD identifier, model name, software version, operating systems, transfer method (Telematics), public instructions URL, public contact. Certifying statement (5.2) referencing the Stage E test description.
  • Decided 10 September: one registration and one ELD identifier covering both operating systems; the public URL holds the user manual, the transfer and malfunction sheets, and a contact. Still with Tom Cuthbertson: which version changes require re-submission (5.1.2).
  • FMCSA has revoked about 80 registrations this year, targeting chameleon and white-label devices. The registration is a self-certification with a statement of how the device was tested; the Stage E evidence is what defends it.
  • Listing appears within one to five business days. Pilot runs in parallel.
  • Keep registration current (5.1.2). Maintenance runbook: FMCSA guidance changes, re-submission on major version, app-store re-review, driver-reported edge cases, annual user-guide refresh, response procedure for a removal notice (5.4: notice, response, agency action, administrative review).
  • Watch item (Tom Cuthbertson, 14 September): FMCSA has pursued wireless roadside inspection at scale houses since the 1995 pilot and is now "two to three years away." It would send header data, the driver's CDL and an hours summary ahead of the truck through PrePass or Drivewise. Heavy-haul construction fleets are a target because scales cannot take them. No build impact now; track in the runbook.

Exit. Device listed on the FMCSA registry; maintenance runbook staffed. Evidence: public listing and the runbook.
